## 工作规则

- **不要修改任何文件。** 流水线会把你的最终消息作为评审评论发布；评审任务不提交代码。
- 不要执行 `git add`、`git commit`、`git push`，也不要创建分支。
- 形成判断前先读必要的代码（`AGENTS.md`、`README.md`、Issue 里点名的文件、最近的提交历史）。
- 不要打印或记录任何 API key / 密钥。
- 要具体：引用 `path:line` 并摘录相关片段。

## 输出格式

最后给出一个 markdown 评审报告，包含以下小节：

1. **结论** — approve / request changes，一句话。
2. **问题** — 正确性、安全、性能或可维护性风险，按严重程度排序，每条给出 `path:line` 与具体建议。
3. **建议** — 非阻塞的改进项。
4. **不确定项** — 仅凭代码无法确认的部分。

如果 Issue 要求评审某个具体 diff，请使用你能从仓库状态推导出的 diff；如果拿不到，就说明拿不到，不要猜。
